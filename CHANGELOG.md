# Changelog

All notable changes to this provider are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.1.0] — 2026-09-24

Additive release. New task-group management resources, a full documentation
generation pipeline, release automation, and enriched schema descriptions.
No breaking changes — every attribute and block name from 1.0.0 is preserved.

### Added

- **Task groups.** New resources and data sources covering the RMS device
  task-group surface (`/devices/tasks/groups`, and `/devices/tasks?group_id=…`
  for composing task lists on read).

  | Name | Kind | Notes |
  | --- | --- | --- |
  | `teltonika_rms_task_group` | Resource | Full CRUD. `tasks` is a typed list-of-objects; each entry accepts an inline literal or a resource reference. |
  | `teltonika_rms_task_group_task` | Resource | **State-only helper** — performs no RMS API calls at any lifecycle stage. Exists so task definitions can be named, reused across groups, and spliced into a group's `tasks` list as an object value. |
  | `teltonika_rms_task_group` | Data source | Single group + its tasks in execution order. |
  | `teltonika_rms_task_groups` | Data source | Every task group visible to the token. |

- **Documentation pipeline.**
  - Every resource and data source ships with a schema `Description` sourced
    from the RMS OpenAPI
    (`https://api.rms.teltonika-networks.com/openapi/compiled.yaml`) —
    endpoint mappings, field constraints (length limits, enums, formats),
    and cross-references between related resources.
  - Markdown docs under `docs/` are generated by
    [`tfplugindocs`](https://github.com/hashicorp/terraform-plugin-docs)
    and ingested verbatim by the Terraform Registry. Regenerate with
    `make docs`; enforce freshness in CI with `make docs-check`.
  - `examples/` restructured into per-block folders per tfplugindocs
    convention (`examples/resources/<TYPE>/resource.tf`, `import.sh`,
    `examples/data-sources/<TYPE>/data-source.tf`), so each page renders a
    working Example Usage block and Import snippet.

- **Release automation.**
  - `.goreleaser.yaml` produces the signed release artifacts the Terraform
    Registry pulls: per-platform zips, `SHA256SUMS`, `SHA256SUMS.sig`,
    `terraform-registry-manifest.json`.
  - `.github/workflows/release.yml` runs GoReleaser on any `v*` tag push,
    importing a GPG key from `GPG_PRIVATE_KEY` / `PASSPHRASE` repo secrets.
  - `terraform-registry-manifest.json` declares protocol v6.
  - Registry publication remains optional — `make install` keeps everything
    local.

### Changed

- **Scope statement rewritten** to reflect actual coverage (~17 % of the
  API's 236 operations) and to split the unwired surface into "imperative
  actions (Terraform shouldn't model these)" and "management-shaped
  follow-on work", with a concrete list of the biggest gaps in each bucket.
  See **Scope & known limitations** below.

## [1.0.0] — 2026-09-23

Initial release. Terraform provider for the [Teltonika RMS API](https://developers.rms.teltonika-networks.com/pages/api.html),
built on the Terraform Plugin Framework.

### Provider

- Address: `registry.terraform.io/lombare/teltonika-rms`.
- Local block name: `teltonika` (Terraform disallows underscores in provider local names); resource/data-source prefix `teltonika_rms_*`.
- Authenticates with a Personal Access Token (Bearer). Configurable via `token` in
  the provider block or the `TELTONIKA_RMS_TOKEN` environment variable.
- Optional `base_url` (or `TELTONIKA_RMS_BASE_URL`) for staging or on-prem RMS
  deployments; defaults to `https://rms.teltonika-networks.com/api`.

automations, data-collect configs, configurator templates) accept a raw JSON
`payload` attribute matching the OpenAPI request body — this keeps the provider
compatible with the full RMS grammar without pinning us to one shape.

### Install

```sh
git clone https://github.com/lombare/Terraform-Provider-Teltonika-RMS.git
cd Terraform-Provider-Teltonika-RMS
make install
```

`make install` drops the plugin under
`~/.terraform.d/plugins/registry.terraform.io/lombare/teltonika-rms/<version>/<os_arch>/`
so Terraform resolves the source `registry.terraform.io/lombare/teltonika-rms`
locally without any registry publication.

### Scope & known limitations

- Covers the management-shaped surface of the RMS API — everything creatable,
  updatable, or deletable is a resource; useful read endpoints are data sources.
  Roughly ~14 % of the API's 236 operations are wired in this release. The
  remaining surface splits into:
  - **Imperative actions** (device commands, firmware updates, RMS Connect
    session opens, credit movement, report generation, remote-access URL
    minting, configurator apply, VPN quick-hub bootstrap, eSIM operations) —
    Terraform is a poor fit for these, and they will remain outside the
    provider's scope.
  - **Missing management-shaped resources** — task groups (added in 1.1.0),
    file upload/edit, reports, images, credit codes, VPN routes/DHCP/
    settings/custom-users/device-attach, remote-access URL entries, device→
    automation and device→data-collect attachments, per-device alert
    bindings, device metadata updates. These are natural follow-on work in
    the same pattern.
  - **Missing read-only data sources** — device logs, information history,
    data usage, locations, hotspot users, wireless telemetry, automation
    logs, VPN sessions/logs, credits history, task/task-group execution
    logs, configurator specification, aggregate company data.
- `teltonika_rms_user_invitation` and `teltonika_rms_device_tag_assignment`
  trust local state on read: RMS does not expose a get-single endpoint for
  invitations, and no single endpoint returns just the tag set for a device.
  Drift is corrected on the next apply rather than surfaced in `terraform plan`.
- `teltonika_rms_configurator_template` requires replacement on payload change —
  RMS has no update verb for templates.

### Security

- All dependencies are on versions that patch the currently disclosed advisories
  (`golang.org/x/net` v0.59.0, `google.golang.org/grpc` v1.84.0).
- Sensitive attributes (`token`, `password`) are marked so Terraform redacts them
  from plan output and state diffs.

### Compatibility

- Terraform ≥ 1.0.
- Go 1.24+ to build from source.
- Tested against RMS API v3 (BETA); schemas derived from the OpenAPI spec
  fetched on the release date above.
